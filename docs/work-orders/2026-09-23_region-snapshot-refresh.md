## 2. ★★★ 원인 — 스냅샷이 어제 것이고, 새로 받아도 옛것이 옵니다

```
src/data/tradule_regions.json   ←  9/22 에 받은 137곳
```

`npm run regions:refresh` 를 돌려도 해결이 안 됩니다.

```js
// scripts/refresh-tradule-regions.js
await axios.get(`${apiBase}/api/content/regions`, { timeout: 15000 });
```

**쿼리 없이 부르면 트레쥴 CDN 이 최대 24시간 옛 응답을 줍니다.** 지금 실측이 이렇습니다.

```
/api/content/regions          →  137곳 · 22개국    ← 옛것
/api/content/regions?cb=123   →  153곳 · 26개국    ← 새것
```

### 고칠 것

```js
await axios.get(`${apiBase}/api/content/regions`, {
  params: { v: Date.now() },          // CDN 우회
  headers: { 'Cache-Control': 'no-cache' },
  timeout: 15000,
});
```

**트레쥴 쪽에도 캐시를 1시간으로 줄이라고 요청했지만, 여기서도 우회하는 게 안전합니다.**

## 처리 결과 (2026-09-23)

- §2: `scripts/refresh-tradule-regions.js`·`cli.js`의 `fetchRegions()` 둘 다
  캐시 버스터(`v=Date.now()`) + `Cache-Control: no-cache` 헤더로 CDN 우회.
  세션 시점 재조회 결과 무쿼리/캐시버스터 둘 다 153곳으로 이미 일치(직전
  D-047 갱신이 반영된 상태) — 코드 방어만 추가, 데이터는 이미 최신.
- §3: 전체 재설계(파이프라인 시작 시 항상 라이브 조회 후 REGION_TREE 등
  모듈 상태 재구성)는 이번엔 구현하지 않음 — 대신 cli.js의 `fetchRegions()`가
  이미 매 실행마다 라이브 조회하던 것에 "성공 시 스냅샷 파일에도 덮어쓰기"를
  추가해, cli.js를 거치는 실행에서는 다음 파이프라인 프로세스가 최신 스냅샷을
  읽게 했다. cli.js를 거치지 않는 자동화 실행(cron 등)까지 커버하려면
  `tradule_source.js`의 동기 로드 구조 자체를 리팩터링해야 하는데, 이번
  범위에서는 하지 않음 — 아래 "다르게 한 것" 참고.
- §4: `cli.js`의 `REGION_ALIASES`에 `발리→우붓`, `코타→코타키나발루` 추가.
- §5: `attachTripData()`가 웹 검색 폴백 전에 `fetchCourseBriefWithRetry()`로
  실제 course-brief를 라이브로 한 번 불러 확인 — 성공하면(평점 있는 스팟
  MIN_SPOTS 이상 + 일자 간 도시 변경 없음) 진짜 트레쥴 데이터로 처리하고
  웹 검색은 시도하지 않는다. 404 응답의 `suggestions` 필드 파싱은 실제 응답
  포맷을 검증할 방법이 없어 구현하지 않음 — 기존 `suggestChildRegions()`
  (로컬 parent→children 매핑 기반)를 그대로 유지.
