# 작업 지시서 — 지역 × 일수 네이버 검색량 리포트 (트레쥴 "대표 일수" 근거 데이터)

작성: 2026-10-13 · 대상: **AutoPipeline** (`ldg1220-debug/AutoPipeline`)
목적: "사람들이 그 지역을 실제로 며칠로 가는가" 를 추측이 아닌 **네이버 검색량**으로 정함. 결과는 트레쥴 지역별 대표 일수에 들어감.

## 0. 먼저 — 이 지시서를 저장소에 보관

1. `docs/work-orders/2026-10-13_region-days-volume-report.md` 로 저장
2. **완료된** 지시서 중 오래된 것부터 지워 10개 유지 (미완료 건은 남길 것)
3. 본 작업과 **같은 PR에** 포함

## 0-1. 배경 (처음 보는 세션용)

- 트레쥴 코스 페이지는 `/course/{지역}/{N박M일}` 입니다. 지역마다 "대표 일수"(허브 첫 칩 · 크롤 우선순위)를 정하려 합니다.
- 휴양지라도 거리(비행시간)에 따라 많이 가는 일수가 다릅니다(오키나와 2박3일 vs 코타키나발루 4박6일~5박7일). 이를 데이터로 확인합니다.
- AutoPipeline 은 이미 네이버 검색광고 API(`naverSearchAd`)로 월간 검색량을 조회합니다(keyword_miner 의 검색량 게이트).

## 1. 만들 것 — `scripts/region-days-volume.js` (LLM 호출 없음)

```
입력: 트레쥴 지역 목록 (기존 tradule regions 스냅샷 · 메뉴 10 과 같은 소스)
조합: {지역} + 일수 표기 9종
      당일치기 · 1박2일 · 2박3일 · 3박4일 · 3박5일 · 4박5일 · 4박6일 · 5박6일 · 5박7일
      (띄어쓰기 변형 "2박 3일" 도 함께 조회해 합산)
조회: naverSearchAd 월간 검색량(PC+모바일) — 배치 제한 지켜 나눠 호출, 결과 캐시
출력: output/reports/region-days-volume-YYYYMMDD.json
  { "코타키나발루": { "2박3일": 120, "3박5일": 2400, "4박6일": 1900, "5박7일": 900, ... , "top": ["3박5일","4박6일","5박7일"] }, ... }
  + 같은 내용 CSV (지역, 표기, 검색량)
메뉴: 11번 "지역별 일수 검색량 리포트" 추가 (LLM 비용 0 · 검색광고 API 만)
```

- 검색량 10 미만(<10 으로 오는 값)은 5 로 처리
- `top` 은 검색량 상위 3개 표기
