## 1. 무엇을 만드는가

```
node scripts/write-kin-answer.js \
     --region 오사카 --days 2 \
     --question "오사카 2박3일 처음 가는데 코스 추천해주세요. 20대 커플이고 렌트는 안 합니다"

→ output/kin/20260914_오사카_2일.md   (복붙용 답변 초안)
```

**블로그 파이프라인에서 발행만 뺀 것**입니다. 부품은 거의 그대로 씁니다.

```
tradule_source.js       course-brief 호출 → trip_data       ← 재사용
Part 1.7.5 스팟 검수     이상한 스팟 제외                    ← 재사용
LLM 초안 생성           블로그 대신 답변 형식으로            ← 프롬프트만 새로
```

## 2. ★★★ 자동 발행은 만들지 마세요

```
네이버 지식iN은 공개 API가 없습니다.
자동 답변 등록은 약관 위반이고, 계정 정지로 끝납니다.
```

**원고 파일까지만 만들고, 붙여넣기는 사람이 합니다.**
브라우저 자동화(Playwright)로 등록하는 것도 **하지 마세요.**
블로그와 달리 지식iN은 계정 하나가 자산인데, 그걸 걸 이유가 없습니다.

---

## 3. ★★★ LLM이 팁을 지어내면 안 됩니다

제가 쓴 예시에 이런 문장이 있었습니다.

```
"규카츠 모토무라는 웨이팅이 길어서 오픈 시간에 맞춰 가시는 걸 권합니다"
```

**이 한 줄이 답변의 값어치를 결정합니다.** 그런데 LLM이 지어내면
`channel_strategy.json`의 **"가보지 않은 곳을 다녀온 것처럼 쓰기" 금지**를 정면으로 어깁니다.
게다가 틀리면 질문자가 손해를 봅니다.

### 대신 — 실제 리뷰에서 뽑으세요

```
GET /api/places/details?placeId=...    →  구글 리뷰 원문
```

```
· 코스 상위 2~3곳의 리뷰를 가져온다
· LLM에게 "이 리뷰들에서 방문 전에 알면 좋을 사실만 요약" 시킨다
· 리뷰에 근거가 없으면 팁을 만들지 말 것 — 빈칸으로 둔다
```

```markdown
<!-- 원고 하단 -->
## ✍️ 여기에 직접 한 줄 (필수)
리뷰 근거: "웨이팅 40분 기다렸어요"(★4, 2개월 전) / "오픈런 추천"(★5, 1달 전)
```

**사람이 마지막 한 줄을 채우게 남겨두세요.** 그게 복붙처럼 안 보이게 하는 유일한 장치입니다.

## 4. 원고 형식

```markdown
# [질문] 오사카 2박3일 처음 가는데...
질문 링크: (붙여넣기)

---
## 복붙 영역 ↓↓↓

오사카 처음이시면 성·전망대 쪽과 항만 쪽을 하루씩 나누는 게 동선상 편합니다.

**1일차 (도심, 총 15km)**
오사카 성 ★4.4 (리뷰 99,648)
→ 59분 · 오니기리 고리짱 ★4.9 (리뷰 13,506)
→ 25분 · 우메다 스카이빌딩 ★4.4 (리뷰 43,408)

**2일차 (항만)**
해유관 ★4.5 (리뷰 61,349)

(여기에 직접 한 줄)

## 복붙 영역 ↑↑↑
---
### 검수 기록
제외한 스팟: 스테이354(평점 없음), 논골집(평점 없음)
리뷰 근거: …
링크 포함: 아니오 (최근 4건 중 1건에 이미 포함)
```

**복붙 영역을 명확히 표시**하세요. 검수 기록까지 같이 붙여넣는 사고를 막습니다.

## 5. ★★ 링크 비율을 코드로 강제

```
네이버는 외부 링크 반복을 스팸으로 봅니다.
```

```
output/kin/history.json 에 기록
  { date, region, questionUrl, linkIncluded }

--link 를 줘도, 최근 5건 중 이미 1건에 링크가 있으면 거부한다
```

**사람이 기억해서 지키는 규칙은 지켜지지 않습니다.** 모듈이 세게 하세요.

---

## 6. ★★ 같은 문장이 반복되면 안 됩니다

같은 지역 질문이 여러 번 옵니다. 매번 같은 도입부가 나가면 네이버가 잡아냅니다.

```
output/kin/ 의 같은 지역 기존 원고를 LLM 프롬프트에 함께 넣고
"아래 문장들과 겹치지 않게 쓸 것" 을 지시
```

코스 자체도 매번 같으면 안 되니, `course-brief` 재호출로 구성이 바뀌는 걸
그대로 쓰되 **바뀌지 않으면 순서를 바꾸거나 한 곳을 교체**하세요.

## 7. ★ 금지 표현 필터

`blog_content_enhancer.js`의 `sanitizeTargetReader` 패턴을 그대로 씁니다.

```
"제가 만든 앱인데"        → 홍보 판정
"저희 서비스"            → 홍보 판정
"30대 직장인" 류 페르소나  → 구 경제채널 잔재
과장 표현("무조건", "필수") → 답변 신뢰 하락
```

## 8. 입력을 유연하게

동근님이 "키워드, 경로 등을 제공하는 식"이라고 하셨습니다.

```
--region 오사카 --days 2                    기본
--spots "오사카성,해유관,도톤보리"            직접 지정 (course-brief 무시)
--exclude "스테이354"                        특정 스팟만 제외
--tone "커플" | "가족" | "혼자"               질문자 조건 반영
```

`--spots`가 있으면 **그 이름들로 `/api/places/search`를 돌려 평점·좌표만 채우고**
순서는 동근님이 준 그대로 씁니다.

## 11. 참고 — 이게 왜 블로그보다 나을 수 있나

```
블로그  202편  →  28일 클릭 1
```

지식iN 답변은 **네이버 검색 상위에 직접 노출**됩니다.
글을 새로 써서 색인되기를 기다리는 게 아니라, **이미 검색되는 질문에 붙는** 방식입니다.

**하루 3개면 한 달 60~70개.** 블로그 202편이 못 한 일을 이게 할 수도 있습니다.
