## 2. ★★★ 틀린 결론

> "서울·부산·제주·인천이 공식 목록에 아예 없었습니다 —
>  이 네 지역으로 된 키워드는 아마 계속 조용히 실패하고 있었을 겁니다."

`/api/content/regions` 의 실제 구조입니다.

```
domestic: [ { name: "종로",   parent: "서울" },
            { name: "해운대", parent: "부산" },
            { name: "양평",   parent: "경기" },  … ]   61개

parent 값:  서울 · 경기 · 인천 · 강원 · 충청 · 전라 · 경상 · 부산 · 제주   9개
```

**`name` 만 보면 부모 9개가 빠집니다.** 그래서 "없다"고 읽으신 겁니다.

그런데 course-brief는 부모도 받습니다. 오늘 직접 호출했습니다.

```
region=서울  →  200 · 12곳 · 영등포전통시장, 고기굽는저녁, 이랜드크루즈 …
region=부산  →  200 · 12곳 · 자갈치시장, 초량밀면, 부전시장 …
region=제주  →  200 · 10곳 · 서귀포매일올레시장, 용머리해안, 오설록 …
region=인천  →  200 · 12곳 · 신포국제시장, 코스모40 …
```

**전부 정상이고, 실제 그 지역 장소입니다.** 발리 같은 오매칭도 없습니다.

## 3. ★★★ 지금 상태가 더 나쁠 수 있습니다

`name` 61개만으로 REGION_TREE를 교체했다면, **서울·부산·제주가 새로 제외됐습니다.**

```
바꾸기 전   하드코딩 30여 곳  —  서울·부산·제주가 있었을 가능성
바꾼 뒤     name 61곳        —  서울·부산·제주 없음
```

```
"서울 여행 코스"  ·  "부산 2박3일 코스"  ·  "제주 3박4일"
```

**국내 여행 검색어 중 가장 큰 것들입니다.** 이걸 버리면 키워드 채굴의 상단이 통째로 빕니다.

### 고칠 것

```
지역 목록 = domestic.map(name)  ∪  domestic.map(parent)  ∪  overseas 동일
            61곳              +  9곳(중복 제외)
```

```
· 키워드에 "서울"이 있으면 그대로 region=서울 로 호출
· 하위 지역명("홍대", "해운대")이 있으면 그것을 우선 사용 (더 구체적)
· 둘 다 있으면 하위 우선
```

**부모를 "실패"로 처리하지 마세요.**

## 6. ★ 검증 방법 — API를 직접 부르세요

"목록에 있나"가 아니라 **"course-brief가 200을 주나"** 가 기준입니다.

```
node -e "fetch('https://www.tradule.co.kr/api/content/course-brief?region=서울&days=2')
  .then(r=>console.log(r.status))"
```

```
목록에 있는데 course-brief 가 404   →  제외
목록에 없는데 course-brief 가 200   →  포함    ← 서울·부산·제주·인천이 여기
```

**목록은 참고자료고, 계약은 course-brief 입니다.**
