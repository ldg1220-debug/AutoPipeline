## 1. §4는 통과했습니다

```
[tradule_source] "일본 여행"     → 지역 매칭 실패    ✅
[tradule_source] "독일 5박 7일"  → 지역 매칭 실패    ✅
```

**국가 단위 매칭이 정확히 막혔습니다.** 좌표 필드는 `lat` / `lng` 입니다 —
평탄한 구조이고 중첩(`latitude`, `coordinate.lat`)은 없습니다. 원본을 옮깁니다.

```json
{ "day":1, "lat":35.8374081139238, "lng":129.209953809161,
  "name":"경주 황리단길", "order":1, "rating":4.2, "category":"관광지",
  "toNextMode":"walk", "reviewCount":7771, "toNextMinutes":3 }
```

`hasInterDayCityJump()` 에서 `lat`/`lng` 로 확정하시면 됩니다.

## 3. ★★★ QA가 없는 데이터를 요구합니다

```
QA 탈락 사유:  "구체 수치 부족 — 평점·리뷰수·거리·시간 등 실제 수치 인용 필요"
같은 로그 위:  "trip_data 없이 통과"
```

**평점·리뷰수·거리는 trip_data 에만 있습니다.** 없는 걸 요구하니 영원히 통과 못 합니다.

세션에서 "구조적 이슈일 수 있다"고 보신 판단이 맞습니다. **무한 루프입니다.**

### 고칠 방향 — 기준 완화가 아니라 진입 차단

```
❌  trip_data 없는 글용으로 QA 기준을 낮춘다
      →  숫자 없는 글이 발행됩니다.  215편 써서 클릭 1건인 이유가 그겁니다.

✅  trip_data 가 없으면 그 키워드를 스킵한다
      →  QA 기준은 그대로 두고, 애초에 그 글을 안 씁니다.
```

**제 앞 지시서 §8이 "매칭 실패 또는 스킵"이었는데, 지금은 "통과"입니다.**
스킵으로 바꿔주세요.

```
attachTripData 가 trip_data 를 못 붙이면
  → 그 키워드는 발행 대상에서 제외
  → 로그: [tradule_source] "일본 여행" → 코스 데이터 없음, 스킵
```

### 대신 대체 키워드를 제안하세요

"일본 여행"을 버리는 게 아깝다면, 하위 도시로 갈아타면 됩니다.

```
"일본 여행"  →  매칭 실패
             →  parent="일본" 인 하위 지역 중 하나를 제안
                (오사카 · 후쿠오카 · 도쿄 · 교토 · 삿포로 …)
             →  "오사카 2박3일 코스" 로 대체 진행
```

**국가 키워드는 검색량이 커도 코스 글로는 성립하지 않습니다.**

## 4. ★★★ `--force-keyword` 가 채굴을 안 건너뜁니다

```
11:11:51  --force-keyword: "독일 5박 7일"
11:11:51  [keyword_miner] 여행 시드 생성: 나라·나고야·요코하마·고베·오키나와 …
11:12:06  [naverSearchAd] 조회 성공: 101개 키워드 (배치 8/8건)
11:12:07  키워드 2개 선택
```

**키워드를 직접 줬는데 30초간 채굴을 다 돕니다.** 네이버 API 8배치도 씁니다.

그리고 최종 후보에 **제가 주지 않은 키워드**가 같이 올라옵니다.

```
1. 독일 5박 7일          ← 내가 준 것
2. 오사카 고베 당일치기    ← 채굴에서 나온 것
```

```
--force-keyword 가 있으면
  · 채굴 · 검색량 조회 · DB 보충 전부 스킵
  · 그 키워드 하나만 진행
```

**지정했는데 왜 고르라고 물어보는지 이해가 안 됩니다.** 선택 화면도 건너뛰세요.

## 처리 결과 (2026-09-22)

- §1: `spotLatLng()`가 이미 `spot.lat`/`spot.lng`를 우선 시도하고 있어 그대로 동작함을
  확인 — 확정된 평탄 구조에 맞춰 중첩 필드(`latitude`, `coordinate.lat` 등) 추측
  코드를 제거하고 `{ lat, lng } = spot`으로 단순화 (`src/agents/tradule_source.js`).
- §3: `attachTripData()`에서 지역 매칭 실패 시 `item.category === 'travel'`이면
  `skip_reason`을 남겨 발행 대상에서 제외(`run-blog-pipeline.js`가 이미
  `skip_reason` 있는 항목을 필터링하는 구조를 그대로 활용). travel이 아닌 키워드는
  기존대로 trip_data 없이 통과(전체 키워드를 다 스킵하면 안 되므로). 국가/광역권
  이름이 그대로 포함된 키워드는 그 부모의 자식 지역 후보를 로그로 제안
  (`suggestChildRegions()`, 자동 치환은 하지 않음 — 도시 선택은 편집 판단 필요).
- §4: `--force-keyword`가 `--single`(채굴 스킵)과 `--auto`(선택 화면 스킵)를
  자동으로 내포하도록 변경 (`run-blog-pipeline.js`).
- §5: `--force-category`를 명시하지 않으면 `looksLikeTravelKeyword()`로 지역명
  포함 여부를 판정해 category를 자동으로 `travel`/`economy`로 설정
  (`src/agents/tradule_source.js`에 신규 export, `run-blog-pipeline.js`에서 사용).
  이게 "구 경제채널 페르소나" 경고의 근본 원인이었음 — category=economy가 Pass1
  프롬프트에 그대로 들어가 LLM이 경제 채널 페르소나로 드리프트했다.
- §6: QA 탈락 사유에서 `"단어" N회` 패턴을 뽑아 재작성 프롬프트에 명시적 상한
  지시를 추가(`src/agents/blog_content_enhancer.js`). 재작성은 기존에도 1회로
  하드캡되어 있어(코드 확인) 별도 "2회 중단" 로직은 불필요했음.
- §7: `runBlogLLMQA()`가 섹션 3개×200자만 넣던 것을 전체 섹션 전문으로 교체하고,
  "잘린 게 아니라 전문"임을 프롬프트에 명시(`src/agents/qa_editor.js`). 같은 함수의
  "한국 경제 블로그 SEO 전문가" 페르소나도 "여행 블로그"로 수정(§5와 같은 계열의
  잔재였음).
