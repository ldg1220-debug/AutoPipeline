## 2. ★★★ 가장 심각한 것 — 검수 단계가 우리 숫자를 지웁니다

2차 실행 로그입니다.

**평점·리뷰수·이동시간·거리는 트레쥴이 준 값이고, 우리 글의 유일한 차별점입니다.**

전에 Pass 5 가 "트레쥴 앱"을 허구 브랜드로 오탐했던 것과 같은 원인입니다 — **검수자에게 근거 데이터를 안 줬습니다.**

### 고칠 것

```
① Pass 4·5 프롬프트에 trip_data(스팟명·평점·리뷰수·구간 분·일자별 km)를 넣고
   "이 값과 일치하는 숫자는 수정 금지" 를 명시

② 코드 가드 (프롬프트만으로는 또 뚫립니다)
   Pass 5 전후로 본문의 ★/평점 · 리뷰 N · N분 · N km 개수를 셉니다
   Pass 5 후 개수가 줄었으면 → Pass 5 결과를 버리고 Pass 5 이전 본문 사용
```

**②가 핵심입니다.** 검수가 숫자를 지우면 검수를 무효로 하세요.

> 참고: 로그 라벨은 `Pass 5 (Claude review)` 인데 실제로는 `gemini-2.5-flash` 가 돕니다.

## 3. ★★★ 게이트② — 착수하세요. 다만 "일정을 LLM이 쓰지 않게" 하는 쪽으로

1차 실행 로그입니다.

```
Pass 5: 섹션 2 '시간대별 동선 계획'의 첫째 날 일정이
        섹션 1 '코스 개요' 및 섹션 4 '이동 방법'의 일정과 모순
        (도교 사원 · 산 페드로 요새 · House of Lechon 의 등장 시점 불일치)
```

**같은 글 안에서 LLM 이 일정을 세 번 쓰고 세 번 다르게 썼습니다.**
그리고 Pass 5 가 "교정" 했다는 것도 **trip_data 가 아니라 LLM 판단 기준**입니다. 맞게 고쳤다는 보장이 없습니다.

### 일정의 정답은 이미 글에 있습니다

`monetizer` 가 trip_data 로 만드는 **"🗺️ 동선 타임라인" 표**가 결정론적 정답입니다.
그런데 LLM 이 그 옆에 "시간대별 동선 계획" 을 **또** 서술하면서 표와 다르게 씁니다.

```
할 것
 ① 아웃라인에서 "시간대별 동선 / 일자별 일정 / 코스 개요의 일정 서술" 섹션을 코드로 제거
    (sanitizeOutlineForbidden 과 같은 자리)
 ② 대신 일자별 짧은 해설을 일자마다 따로 생성
      for day in tripData.days:
        프롬프트 = 그날 스팟 목록 + 구간 분 + 그날 km  (이것만)
        출력 = 2~4문장, "이 목록 밖 장소 언급 금지"
        생성 후: 다른 날 스팟명이 나오면 그 문장 삭제
 ③ 나머지 섹션(개요 · 이동 방법 · 팁)에서
    "N일차 / 첫째 날" + 스팟명 이 함께 나오는 문장은
    그 스팟의 실제 일차와 다르면 삭제
```

**"섹션 전체를 일자 단위로 재설계" 가 아니라 "일정 서술을 LLM 자유 서술에서 빼는 것" 입니다.**
규모가 훨씬 작고, 모순이 생길 자리 자체가 없어집니다.

## 4. ★★ 게이트와 QA 가 서로 싸웁니다

```
게이트④  출처 없는 금액 문장 5개 삭제
    ↓
QA       "섹션 글자 수 미달: [시간대별 동선 계획] (최소 600자)"  → REJECTED
```

**지어낸 문장을 지우면 섹션이 짧아지고, QA 는 짧다고 떨어뜨립니다.**
600자를 채우라고 하면 LLM 은 또 지어낸 문장으로 채웁니다. 이게 계속 반복됩니다.

```
섹션 최소 글자 600 → 350
대신 "섹션마다 trip_data 숫자 1개 이상" 을 요구
글 전체 최소 글자는 유지
```

**길이 대신 사실 밀도로 판정하세요.**

## 5. ★★ QA 반려 사유 중 우리 쪽 버그인 것

### ① 섹션 제목에 "##" 가 글자로 들어가 있습니다

```
QA: 섹션 글자 수 미달: [## 세부 2박3일 여행 코스 개요]
QA: H2/H3 태그가 명확히 구분되지 않음          ← 독일 글 때도 나왔던 사유
```

**아웃라인의 섹션 제목 문자열 자체에 `## ` 가 붙어 있습니다.** 렌더링하면 "## 세부…" 가 제목 글자로 찍힙니다.

```
아웃라인 파싱 직후  title.replace(/^#+\s*/, '')
```

### ② 키워드 검사가 띄어쓰기에 걸립니다

```
QA: SEO 키워드 확인 필요: [세부 2박3일]
QA: 본문에 '세부 2박3일' 키워드가 충분히 반복되지 않음
QA: 메타 설명에 키워드가 없음
```

본문이 "세부 2박 3일" 로 쓰면 "세부 2박3일" 과 불일치로 셉니다.

```
키워드 비교 시 공백 제거 후 비교
메타 설명은 LLM 에 맡기지 말고 코드로 키워드를 앞에 붙이세요
  meta = `${keyword} — ${spotCount}곳, ${요약}`
```

## 처리 결과 (2026-09-29)

- §2①: `buildTripDataFactsBlock()` 신규 — 스팟명·평점·리뷰수·구간 이동시간을
  Pass4·Pass5 프롬프트에 주입하고 "이 값과 일치하는 숫자는 수정 금지" 명시.
- §2②(핵심): `countFactNumbers()` 신규(★평점·리뷰수·N분·N km 카운트) — Pass4·
  Pass5 각각 검수 전후 개수를 비교해, 검수 후 줄었으면 검수 결과를 버리고
  검수 이전 본문을 사용하도록 코드 가드 추가. standalone 재현 테스트로
  "★4.4, 리뷰 12,274개, 도보 14분, 1.2km" → 4개 감지, "평점이 높은 곳" →
  0개 감지 확인(가드가 정확히 발동하는 경우를 확인).
- 로그 라벨: `"Pass 5 (Claude review)"` → `"Pass 5 (Gemini review)"`로 정정
  (실제로 gemini-2.5-flash가 돔). Pass5 프롬프트의 "한국 경제·생활 블로그"
  페르소나도 "한국 여행 블로그"로 함께 정정(같은 계열 잔재).
- §5①: `pass2Outline()`에서 아웃라인 파싱 직후 title·section heading에서
  `/^#+\s*/` 제거.
- §5②: `qa_editor.js`의 SEO 키워드 검사를 공백 제거 후 전체 구 비교로
  우선 확인(실패 시에만 토큰 단위로 완화 검사) — "세부 2박3일"과 "세부
  2박 3일"을 같은 것으로 인식하도록 정정. meta_description은 trip_data가
  있으면 LLM에 맡기지 않고 코드로 `"${keyword} — 실제 코스 N곳, ..."`
  형태로 결정론적 생성.
- §4: `BLOG_MIN_SECTION_CHARS` 600 → 350. `BLOG_MIN_NUMBERS_PER_SECTION`
  (섹션당 구체 수치 2개 이상, 기존에 이미 있던 규칙)이 "사실 밀도" 기준
  역할을 이미 하고 있어 별도 신설 없이 재활용. `BLOG_MIN_TOTAL_CHARS`
  (글 전체 4000자)는 그대로 유지.
- §3(게이트②, 일정 LLM 자유 서술 제거 + 일자별 분할 생성): **착수 안 함** —
  "1~3번만으로도 통과 가능성이 높다"는 지시서 자체의 우선순위 판단을 따라
  이번 라운드에서는 보류. 재발 시 다음 라운드에서 §3①(섹션 제거)부터
  단계적으로 진행 예정.
- §6(페르소나 원본 정리): 프롬프트(`blog_pass1_intent.md`)를 확인했으나
  경제 채널을 언급하는 잔재 문구 자체가 없었음(이미 "이 채널은 여행
  콘텐츠이며 경제 채널이 아니다"라고 명시돼 있음) — "30대 직장인" 드리프트는
  텍스트 잔재가 아니라 LLM의 자체 경향으로 보여, grep으로 제거할 대상이
  없었음. 기존 코드 가드(STALE_PERSONA_PATTERNS)가 이미 안전망 역할을 하고
  있어 추가 조치 없이 현행 유지.
