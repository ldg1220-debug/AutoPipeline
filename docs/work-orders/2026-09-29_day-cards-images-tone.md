## 3. ★★★ 이미지 — 지도는 일자별로, 스톡 사진은 한 장만

```
글 맨 위     전체 코스 지도 1장 (지금 것)
N일차 섹션   그날 동선만 그린 지도 1장     ← 트레쥴에 day 파라미터 요청 (짝 지시서)
스톡 사진     도입부 1장만. 일자 섹션에는 넣지 않음
```

**일자별 지도가 나오기 전까지는 일자 섹션에 이미지를 아예 넣지 마세요.**
같은 사진 다섯 번보다 사진 없는 편이 낫습니다.

```
blog_asset_builder
  · 같은 이미지 URL/ID 는 글 안에서 1번만
  · course-map?day=N 이 200 이면 그 날 섹션에, 아니면 생략
  · Pexels 크레딧 "Photo by Pexels on Pexels" 같은 빈 작가명은 사진째 제외
```

## 4. ★★★ 일자 섹션을 "카드" 로 — 대부분 코드로

지금: 사진 + 화살표 한 줄 + LLM 문단 + 핵심 상자
바꿀 것:

```
### 3일차 — 한식 점심 · 가족 공원   (이동 22분)          ← 부제는 코드가 category 로 만듦

[3일차 동선 지도]                                        ← 짝 지시서 완료 후

| 순서 | 장소 | 종류 | 평점 (리뷰) | 다음 이동 |
|---|---|---|---|---|
| 1 | 풍류정바닐라드 | 한식 | ★4.8 (800) | 대중교통 22분 |
| 2 | D' Family Park | 공원 | ★4.1 (540) | — |

> 이 날의 포인트 — 이동은 한 번(대중교통 22분)뿐이라 여유 있는 날입니다.   ← 코드가 데이터로 만듦

(LLM 해설 1~2문장 — 선택)
```

### 코드로 만드는 "포인트" 문장 예

```
· 하루 이동 합계가 가장 긴 날   → "이동이 가장 많은 날입니다(총 N분). 차량 구간 N분은 그랩을 권합니다."
· 이동이 1구간 이하              → "이동은 한 번뿐이라 여유 있는 날입니다."
· 식당 2곳 이상                  → "점심·저녁을 모두 이 동선 안에서 해결할 수 있습니다."
· 해변 포함                      → "해변은 평점 정보가 없어 방문 전 현장 상황 확인을 권합니다."
· 도보만                         → "하루 종일 걸어서 이동하는 날입니다(총 N분)."
```

**데이터에서 나온 문장은 AI 티가 나지 않습니다.** 숫자가 있고, 매 글마다 다릅니다.

### 없앨 것

```
· "핵심:" 상자 — 전부 제거 (목록·첫 문장 반복)
· 일자 섹션이 있으면 "일별 상세 일정 / 시간대별 동선" 류 LLM 섹션은 아웃라인에서 제거
  (9/28 지시서 §2② — 이번엔 "일별 상세 일정" 이라는 새 이름으로 빠져나감.
   이름 목록이 아니라 "일차·동선·일정" 단어가 들어간 섹션은 모두 제거)
```
