## 1. 지금 문제

```
node scripts/run-blog-pipeline.js --force-keyword "삿포로 3박4일 코스" --force-category travel
node scripts/write-kin-answer.js --region 오사카 --days 2 --question "..." --tone 커플
```

**매번 이걸 외우거나 찾아야 합니다.** 지역 이름이 맞는지, 옵션 철자가 맞는지도
실행해봐야 압니다. 하루 3개씩 답변을 쓰려면 이 마찰이 그대로 비용입니다.


## 3. 흐름 — 지식iN (2번)

```
[1/4] 지역
  국내  1 경주  2 부산  3 강릉  4 여수  5 전주  6 속초 … (더 보기: m)
  해외  21 오사카  22 후쿠오카  23 도쿄  24 방콕  25 다낭 …
  직접 입력: 지역명을 그대로 치세요
선택 > 22

[2/4] 일수
  1  당일       2  1박2일     3  2박3일     4  3박4일
선택 > 3

[3/4] 질문 원문 (붙여넣고 빈 줄 + Enter)
> 후쿠오카 2박3일 가는데 코스 추천해주세요. 20대 커플이고 렌트 안 합니다
>

[4/4] 옵션
  링크 포함?  (최근 5건 중 1건 — 포함 가능)  y/N > n

────────────────────────────
  후쿠오카 · 2박3일 · 링크 없음
  질문: "후쿠오카 2박3일 가는데…"
  이대로 실행할까요? (Y/n) >
────────────────────────────

… 코스 조회 중
… 스팟 6곳 (평점 없는 2곳 제외)
… 리뷰 근거 수집
… 초안 작성

✅  output/kin/20260916_후쿠오카_2박3일.md
    복붙 영역만 그대로 붙여넣으시면 됩니다.
```

### ★ 지역 목록은 하드코딩하지 마세요

```
GET https://www.tradule.co.kr/api/content/regions
  → 국내 61 · 해외 137
```

**매 실행마다 받아 번호를 붙이세요.** 지금 코드의 35개 하드코딩은 지우고요.
트레쥴이 미지원 지역은 `404 unsupported_region`으로 거부하니 안전합니다.

목록이 길면 **자주 쓰는 순으로 상위 10개만 보이고 `m`으로 더 보기**가 낫습니다.

## 4. 흐름 — 블로그 (1번)

```
[1/3] 방식
  1  키워드 직접 지정   2  자동 선정(기존 파이프라인)
선택 > 1

[2/3] 지역·일수   (지식iN과 동일한 선택기 재사용)

[3/3] 발행
  1  초안만 만들기 (발행 안 함)     ← 기본값
  2  티스토리 발행까지
선택 > 1
```

**기본값을 "초안만"으로 두세요.** 실수로 발행되는 것보다 한 번 더 누르는 게 낫습니다.

## 7. 기존 CLI는 남기세요

```
node scripts/run-blog-pipeline.js --auto      ← 스케줄 실행
node scripts/write-kin-answer.js --region …   ← 스크립트에서 호출
```

**런처는 그 위에 얹는 껍데기입니다.** 기존 인자 경로를 없애면 무인 실행이 깨집니다.

```
cli.js  →  질문을 받아 인자를 조립  →  기존 스크립트의 함수를 직접 호출
```

자식 프로세스로 띄우지 말고 **함수를 import 해서 부르세요.** 로그가 섞이지 않습니다.

## 8. 잘못 눌렀을 때

```
· 숫자 아닌 입력      →  다시 묻기 (종료하지 말 것)
· 빈 입력            →  기본값
· Ctrl+C            →  "중단했습니다" 출력 후 깨끗이 종료
· 실행 중 오류        →  어느 단계에서 났는지와 함께 출력
```

**스택 트레이스를 그대로 뱉지 마세요.** "코스 조회 실패 — 지역 이름을 확인하세요" 같은
한 줄이 필요합니다.
