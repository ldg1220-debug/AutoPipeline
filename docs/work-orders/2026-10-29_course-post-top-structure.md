## 1. 새 구조

```
제목   {지역} {N박M일} 코스 | {권역1}·{권역2} 동선 + 시간표          (20~32자)

리드(3문장)
  ① 이 코스의 논리: "{지역}은 {권역A}(대표 명소…)와 {권역B}(…)로 나뉩니다. 1일차 {권역A} 도보, 2일차 {권역B} 차량으로 돌면 이동이 가장 적습니다."
  ② 누구에게 맞는지 (코스 구성에서 도출: 도보 위주 / 테마파크 포함 / 야경 포함 / 섬 포함)
  ③ 이 글에서 볼 것 (시간표 · 장소별 머무는 시간 · 상황별 바꾸기)

목차

H2  한눈에 보는 {지역} {N박M일} 시간표
    표: 일차 | 시간 | 장소 | 이동 | 핵심 포인트(1구절)
    시간 = 09:30 시작 + 머무는 시간(§2) + 이동 분, 5분 단위 — "권장 예시" 라고 명시
    코스 지도

H2  {지역} 코스의 권역 — 왜 이렇게 나눴나
    권역별 2~3문장 (위키보야주 지역/구역 문서 근거 + 트레쥴 좌표: "서로 도보 15분 안" 같은 데이터 사실)

H2  1일차 {시간대}: {권역A} — {핵심 행동}       (예: "1일차 오전~오후: 대릉원·첨성대 — 도보로 신라 고분 산책")
    권역 소개 1문단
    H3 {장소}  ·  머무는 시간 {N분} · 추천 시간대 {오전/일몰/야간 — 근거 있을 때만}
       무엇인지 → 무엇을 보는지/하는지 (위키 근거 2~4문장)
       사진 1장 (Wikimedia Commons, 라이선스 캡션)  ← 3단계 앞당겨 1단계에 포함
       📌 팁 1줄 (근거 or 데이터)
       → 다음: {장소} {수단} {분}
    식당·카페: H3 대신 "이 권역에서 먹고 쉬기" 목록 — 이름(종류 · 코스상 위치 한 구절)  ← 트래비식
    일자 지도

H2  상황별로 바꾸기
    - 비 오는 날: 코스 안 실내 장소(박물관·수족관·시장·전망대 실내)만 묶은 대안 순서
    - 아이와 함께: 테마파크·수족관·공원 포함 날 강조 / 도보 긴 날 경고(데이터)
    - 야경을 넣고 싶다면: 전망대·야간형 장소를 그날 끝으로 (데이터)
    - 하루 더 있다면: 트레쥴에서 days+1 코스로 추가되는 권역 1문장 + 링크
    (근거·데이터로 못 쓰는 항목은 생략)

H2  떠나기 전 체크리스트   (도보 합계·차량 구간·섬 배편 등 데이터 기반 + 쿠팡 준비물 1~2)
H2  자주 묻는 질문 5개    (차 없이 가능? / 하루 몇 곳? / {대표명소} 몇 일차? / 비 오면? / 며칠이 적당? — 데이터로 답)
H2  마무리 + 트레쥴 CTA
출처 블록
```

## 2. 데이터 규칙 (지어내기 금지)

```
① 머무는 시간 — 카테고리 표(코드 상수, 근거 = 일반 관람 소요 범위, "권장" 표기)
   사원·성당·유적 60 · 박물관 90 · 시장 60 · 전망대 45 · 해변 60 · 공원 45 · 카페 40 · 식사 60 · 테마파크 종일 · 섬 반나절
② 추천 시간대 — 위키보야주/위키 문장에 "야경·일몰·아침" 등이 있을 때만, 또는 트레쥴 야간형 규칙으로 그날 끝에 놓인 경우("야간에 보도록 마지막에 배치")
③ 권역 이름 — 위키보야주 구역 문서명 또는 대표 명소 2개 결합("대릉원·첨성대 일대"). 지어낸 동네 이름 금지
④ 사진 — Commons 라이선스 CC0/PD/CC BY/CC BY-SA 만, 작성자·라이선스 캡션 필수, 장소당 1장 · 글당 최대 6장
⑤ 기존 사실 검증 패스(§2 ⑤ of 10/27)는 리드·권역 설명·상황별 문단에도 적용
```

