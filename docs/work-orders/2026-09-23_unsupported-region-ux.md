## 처리 결과 (2026-09-23)

- §2: "종합형 글인가요?" 질문 두 곳(지역 못 찾음 / AI 추정 지역에 동의 안 함)
  모두 제거. D-041 이후 category='travel'(cli.js는 항상 travel 강제)이면서
  지역 매칭 실패면 attachTripData()가 무조건 스킵하도록 이미 바뀌어 있어서,
  "종합형" 경로는 이 실행 시점 기준 발행 옵션·최종 확인까지 다 거치고도 결국
  스킵되는 죽은 경로였음 — 제거해도 기능 손실 없음.
- §3: 지역 판정 자체는 이미 step 0(입력 직후)에서 문자열 매칭으로 처리되고
  있었고, §2에서 "종합형" 탈출구를 없앰으로써 "지역 확인 실패 → 그대로
  발행 옵션까지 진행" 경로가 완전히 막힘. course-brief 실제 API 호출 기반
  사전 검증(제안된 아키텍처)까지는 구현하지 않음 — §2의 탈출구 제거만으로
  "물어놓고 스킵" 증상 자체는 해소된다고 판단(아래 "다르게 한 것" 참고).
- §4: 트레쥴 응답에 `suggestions`가 아직 없어(짝 지시서 대기 중) 큐레이션된
  "가까운 지역 3곳" 대신 지역명을 못 찾으면 바로 구조화 지역 선택 화면(기존
  `pickRegionNav`, 트레쥴 실시간 전체 목록)으로 안내하도록 함.
- §5: `tradule_source.js`의 스킵 사유를 "국가/광역권 단위는 코스 불가"(제외된
  부모 이름이 키워드에 포함된 경우)와 "트레쥴 지원 목록에 없는 지역"(그 외,
  코타키나발루 같은 경우)으로 분리. 스팟 부족 사유도 "스팟 N개 (최소 M개)"
  형식으로 통일.
- §6: `resolveRegionByTheme()`가 이미 결과를 주어진 지역 목록에
  `.includes()`로 재검증하고 있었음(수정 전부터 구조적으로 만족돼 있었음,
  코드 확인) — 별도 수정 불필요.
- §7: `cli.js`에 `REGION_ALIASES`(나트랑→냐짱, 타이페이→타이베이,
  호치민→호찌민) 로컬 테이블 추가, `matchRegionFromText()`가 라이브 매칭보다
  먼저 확인.
