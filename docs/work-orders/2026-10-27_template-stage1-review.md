      추출식 문장이 어색/부정확: "재래시장의 특이한 점을 보면 한국식 음식들을 많이 진열되는…" (위키 문장 그대로 · 사실성 의심)

## 2. 결정 — 설명 비율 높이기 (2단계 전에 먼저)

```
① 좌표 기반 위키 검색 (이름 매칭보다 먼저)
   ko.wikipedia API: action=query&list=geosearch&gscoord={lat}|{lng}&gsradius=300&gslimit=5
   후보 중 (a) 이름 유사도(한글/로마자/한자 정규화) 또는 (b) 문서 카테고리가 관광지/건축물/시장/공원/사찰 … 이면 채택
   ko 에 없으면 en.wikipedia geosearch → 영어 요약을 근거로 한국어 재작성(출처는 영어 문서 링크)
   식당·카페·숙소는 여전히 조회 안 함
② 위키보야주 지역 문서(ko→en)의 "보기·하기" 항목 중 장소명 일치 항목을 보조 근거로
③ 목표: 명소·전망대·시장·공원·사찰·박물관류 장소의 80% 이상에 근거 설명 (오사카 샘플 기준 해유관·신세카이·하루카스 포함)
④ 추출식 대체는 쓰지 말 것 — LLM 재작성이 실패하면 그 장소는 "코스상 역할 1문장" 으로 (어색한 위키 원문 붙여넣기 금지)
⑤ 재작성 프롬프트: "근거 문서의 사실만, 2~4문장, 이 장소가 무엇인지 → 무엇을 보거나 하는지 → (근거에 있으면) 언제 가면 좋은지. 근거에 없는 연도·수치·평가 금지"
```

## 3. 함께 고칠 것

```
- og:description · TL;DR · 리드 등 "평점·리뷰" 문구 전부 제거 (QA 정규식에 메타 태그도 포함)
- 일정 조율 팁: 아래 경우에만 1줄
    그날 가장 긴 구간이 30분 이상 → "○○→○○ 구간이 가장 깁니다. 이 구간만 택시로 바꾸면 …분 줄어듭니다"(차량 시간이 데이터에 있으면)
    야간형이 있으면 → "○○는 저녁에 두는 게 좋아 마지막에 배치했습니다"
    종일시설 날 → 기존 문구
  해당 없으면 생략
- 오사카 샘플 1,862자 < 2,000 — ① 이 적용되면 자연히 넘어야 함. 넘지 못하면 기준을 낮추지 말고 그 코스는 스킵
```
