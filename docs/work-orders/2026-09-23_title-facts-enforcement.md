## 2. ★★★ 그런데 제목·본문이 "5박 7일"이라고 하고 코스는 3일입니다

```
/265  제목 "코타키나발루 5박 7일 여행 코스, 팁"
      본문 "5박" 13회   ·   실제 코스  1일차 ~ 3일차

/267  제목 "발리 5박 6일, …"
      본문 "5박" 16회   ·   실제 코스  1일차 ~ 3일차

/266  제목 "시드니 5박 7일 대중교통 여행 코스"
```

`extractDays()` 가 "5박 7일" 을 days=3 으로 클램프해서 코스는 3일치를 받아옵니다(D-042).
**그런데 제목과 본문의 "5박 7일" 은 그대로 둡니다.**

9/16 지시서 §3-④ 에서 이렇게 요청했습니다.

> **절대 큰 일수를 제목에 쓰고 작은 코스를 붙이지 마세요.**
> `⚠️ "4박6일"은 코스 데이터가 최대 3일까지만 있습니다.  1) 2박3일로 바꿔 진행  2) 그대로 진행(제목에서 일수 제거)  3) 취소`

**이 경고가 런처에 없고, 제목도 안 고쳐집니다.**

### 고칠 것 — 코드로 강제하세요

`sanitizeTitleForBannedWords()` 와 같은 자리에 하나 더 두세요.

```
sanitizeTitleDays(title, tripData)
  제목에서 "N박 M일" / "M일" 추출
  M > tripData.days  이면
    → 제목의 일수를 tripData.days 로 교체  ("5박 7일" → "2박 3일")
    → 본문에서도 같은 치환
```

그리고 런처(cli.js)에서 입력 단계에 한 번 알리세요.

```
⚠  "5박 7일"은 트레쥴 코스가 최대 3일까지만 있습니다.
   1  2박3일 코스로 진행   ← 기본값
   2  취소
```

**"프롬프트 지시 + 코드 2차 강제" 패턴을 여기도 적용하세요.** 프롬프트로는 안 됩니다.

## 3. ★★★ "대중교통"이 데이터에 없습니다

해당 지역 course-brief 의 실제 구간 이동수단을 집계했습니다.

```
코타키나발루 d3   walk 7 · car 7 · transit 0     ← 대중교통 구간 0개
우붓(발리)   d3   walk 4 · car 6 · transit 1     ← 차량 과반
시드니       d3   walk 2 · car 3 · transit 3     ← 과반 없음
```

그런데 글은 이렇습니다.

```
/265 코타키나발루   본문 "대중교통" 12회 + 섹션 "대중교통 이용 팁 및 효율적인 노선"
/267 발리          제목 "대중교통과 도보로 즐기는" · 본문 "대중교통" 17회
/266 시드니        제목 "… 대중교통 여행 코스"
```

**코타키나발루는 대중교통 구간이 0개인데 대중교통 섹션이 통째로 있습니다.** 지어낸 내용입니다.

9/16 지시서 §3-②·③ 을 다시 옮깁니다.

```
toNextMode 집계
  transit 과반  →  제목에 "대중교통" 허용 · "대중교통 이용 방법" 섹션 허용
  car 과반      →  "차로 도는" · "주차·렌트/그랩" 섹션
  walk 과반     →  "걸어서 도는" · "도보 동선" 섹션
  과반 없음      →  이동수단을 제목에 쓰지 않음
```

**이것도 코드로 강제하세요.**

```
sanitizeTitleTransport(title, tripData)
  transit 이 과반이 아니면 제목에서 "대중교통" 및 "대중교통과/으로" 구절 제거

sanitizeOutlineTransport(outline, tripData)
  transit 이 과반이 아니면 "대중교통" 이 들어간 섹션 제목을 교체
  (D-041 의 sanitizeOutlineForNoTripData 와 같은 방식)
```

## 처리 결과 (2026-09-23)

- §2: `sanitizeDaysAgainstTripData(text, tripData, keyword)` 신규
  (`src/agents/blog_content_enhancer.js`) — 키워드에 적힌 일수가
  `tripData.days`보다 크면 제목뿐 아니라 각 섹션 본문·FAQ 답변까지 전부
  치환. `cli.js`에도 입력 직후 경고 추가 — "N박 M일"의 M이 `dayGuess.apiDays`
  (최대 3)보다 크면 경고 후 진행 여부를 묻고, 진행하면 키워드 텍스트 자체를
  클램프된 표현으로 고쳐서 이후 모든 단계(제목·본문·DB 저장)가 처음부터
  일관되게 만든다.
- §3: 기존 `sanitizeTitleForTransport()`가 "그 모드가 데이터에 한 번이라도
  있으면 통과"라는 잘못된 기준이었음을 확인(발리: transit 1/11구간뿐인데도
  통과) — 과반(50% 초과) 기준으로 재작성. 같은 과반 로직을 쓰는
  `sanitizeOutlineTransport()` 신규 — 섹션 헤딩에 과반 아닌 이동수단 단어가
  있으면 안전한 헤딩으로 교체(sanitizeOutlineForNoTripData와 같은 폴백
  목록 재사용).
- §4/§5: 별도 조치 없음 — "완벽" 필터는 이미 `bf64a49`에서 적용됨 확인,
  기존 두 편(/264, /267)은 사용자가 직접 수정하기로 함.
